Does critic reward scaling change SAC on Hopper-v4? A pre-registered null result

From-scratch PyTorch SAC · three arms · CPU · 120k steps/run · 3 seeds/arm

Repository: dafahaha/embodied-offpolicy-study · pre-registered 2026-10-01 before any Hopper result was inspected · independent recompute script: docs/assets/recompute_stats.py

Bottom line At 120k CPU steps and n = 3 seeds, the pre-registered contrast (Baseline vs RewardScaled) shows no detectable effect: Welch p = 0.953, mean difference −33.6 return points with a 95% CI of [−1540, 1473], Cohen's d = −0.05. One-way ANOVA across the three arms: F = 0.22, p = 0.811. This is "not detectable at this budget and variance", not "reward scaling has no effect".

1 · Motivation

SAC (Haarnoja et al., 2018) couples the Q-magnitude to the entropy temperature α through the max-entropy objective. A common engineering knob is to multiply the reward entering the critic's Bellman backup by a fixed reward_scale, which shrinks Q-target magnitude. The pre-registered hypothesis was that smaller Q targets reduce critic over-estimation bias and stabilise learning, yielding higher asymptotic deterministic return and faster early learning on Hopper-v4. The goal of the project was not to invent an algorithm: it was to implement SAC correctly from scratch, instrument it, run a controlled multi-seed measurement, and report whatever the data said.

2 · Pre-registered design

The hypothesis and primary outcome were written in PRE_REGISTRATION.md on 2026-10-01, immediately after Pendulum validation and before launching any Hopper run. The logged Bellman target in src/sac.py is:

y = reward_scale · r + γ(1 − done)·(min Qtarget − α·log π)

The logged episode return is always the unscaled env return, so arms are compared on the true objective.

Shared settings across all arms (from configs/sac_hopper_*.yaml):

  • Env Hopper-v4; 120,000 env steps per run; 1 gradient step per step after 1000 warmup steps.
  • 256×256 MLPs; Adam lr 3e-4; γ = 0.99; τ = 0.005; batch 256; replay buffer 1e6.
  • Deterministic eval: 5 episodes per eval point, every 5k steps; asymptotic window = last 4 eval points (105k–120k).
  • Seeds 0, 1, 2 per arm; CPU only, 4 torch threads; no Hopper hyperparameter tuning.
Pre-registered vs added later The primary confirmatory contrast is Baseline vs RewardScaled. The FixedAlpha arm, the three pairwise Welch tests, and the one-way ANOVA were added after the first 60k pass as exploratory post-hoc analyses and are uncorrected for multiple comparisons; they are reported descriptively only. See Methodology & honesty.

3 · Implementation & end-to-end validation

SAC is implemented from scratch in PyTorch (no Stable-Baselines3): uniform circular replay buffer, tanh-squashed diagonal-Gaussian actor whose analytic log-prob includes both the tanh Jacobian and the linear action-rescale Jacobian, twin critics with min-over-Q, soft target updates, and automatic entropy temperature. Before any Hopper run the loop was validated on Pendulum-v1: deterministic eval return improved from roughly −1600 to roughly −85 within 6k steps (per RESEARCH_RETRO.md). CI keeps a loose learn gate (Δ ≥ 150) that asserts the deterministic eval return actually improves on Pendulum rather than merely running.

Descriptive training dynamics (last logged train row per seed)

Reward scaling couples to the auto-tuned temperature, which is why the FixedAlpha control was added. From the committed CSVs: final α mean ≈ 0.080 (Baseline; per-seed 0.066, 0.106, 0.068) vs ≈ 0.0055 (RewardScaled; 0.0037, 0.0066, 0.0063), and FixedAlpha holds α = 0.2 by construction. Final mean Q₁: Baseline ≈ 170, RewardScaled ≈ 19, FixedAlpha ≈ 36. These are descriptive, not inferential.

5 · Why this null result is worth reporting

  • The tempting result overturned. The first 60k pass looked like reward scaling won by ~3× (narrative in RESEARCH_RETRO.md; those old CSVs are not committed). Restoring the pre-registered 120k budget and adding the fixed-alpha control showed that gap was early-training seed noise, not a benefit.
  • Pre-registration survived contact with the data. The direction was registered in advance; when the data came back null, the conclusion was written as null rather than reframed.
  • The control arm isolates a confound. Reward scaling acts through two paths — Q-target magnitude and the auto-tuned α trajectory. Without FixedAlpha, any apparent difference could not be attributed to critic bias alone.
  • Variance is reported, not smoothed. One seed per arm runs away to ~1800–2100 while others sit ~600–1000; raw seed dots are shown rather than a tidy 1.96×SEM interval that would look falsely precise.

6 · The bug that taught the workflow lesson

The first Pendulum run appeared to learn nothing: Q-values went positive despite all-negative rewards, and deterministic eval returned the same bad number at every checkpoint. A 20-line diagnostic found log π exploding to ~1e15: the Gaussian log-prob was centred at zero x² instead of at the predicted mean (x − μ)², and that spurious gradient collapsed the policy. One-line fix, but the lesson was operational: check the quantities that must have the right sign/magnitude (Q sign here) before concluding "more data will fix it". The fix is locked by analytic log-prob tests in tests/test_core.py (including a non-zero-mean, non-unit-std case checked against scipy's multivariate-normal logpdf).

Hopper-v4 reward semantics are unchanged across these minor bumps; the discrepancy is logged in the README rather than retro-edited into the pre-registration.

8 · Honest limitations

  • Single environment (Hopper-v4), 120k steps, CPU only — not SOTA, not a 1M-step benchmark.
  • n = 3 with this seed variance gives essentially no statistical power; a null here means "not detectable", never "no effect". Modest effects would be invisible.
  • No observation normalisation; bootstrap on time-limit truncation (correct), but rewards are not normalised.
  • Multi-threaded CPU torch reductions are not bit-deterministic; re-runs reproduce the qualitative result, not identical floats (hence the loose learn gate).
  • FixedAlpha and the post-hoc tests are uncorrected exploratory analyses.
